# Qt port code parity ledger

This ledger compares the current Tk behavior and geometry owners with the Qt
implementation. A source match must also survive rendered Mac and Windows
checks at the same **client** size and DPI. Tk's `window_logical_metrics().px`
and `ScenePainter` geometry, parent grid constraints, and the active route all
contribute to final bounds; matching one literal width is insufficient.

The complete code-file index is generated by
`engineering-quality/runners/qt-port-source-index.py` and currently records
566 files at this checkpoint (Python and QML modules under `yt_downloader`, plus
tests, harness, scripts, packaging and CI). It records content hashes,
top-level Python symbols and local imports. The index makes omissions visible;
it is not a parity result. Each Tk-specific presentation owner and every
packaging/harness entry still needs the code-path and rendered checks below.
`qt-port-owner-review.md` maps each Tk presentation file to its Qt path; the
engineering test fails when a newly added Tk presentation file is missing.

States: **wired** means an action reaches an existing owner, **rendered** means
the actual Qt scene was captured, and **open** means the feature or geometry has
not cleared parity. None of these labels claims package or installed proof.
