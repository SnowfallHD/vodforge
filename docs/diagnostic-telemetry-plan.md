# Prospective diagnostic telemetry: evidence contract

Status: source implementation in progress; qualification pending. Existing docs and historical schema2
rows are not evidence that these prospective observations are present. No historical
missing field can be reconstructed. Consent continues to gate the existing owner,
immutable outbox, enrollment, backend and read-only CRM; no second event ledger.

## Intended representation

Keep schema2 transport and existing feature_used storage. Introduce an explicit
instrumentation version and build revision in dimensions. New flow features have
bounded operation UUID correlation and ordinal steps generated by the existing
telemetry owner. UUIDs derive only from random operation/run identity, never source,
media, paths or content. Closed action/stage/outcome vocabularies remain mandatory.
Build revision is a bundled source commit, not a device identifier. Absence is unknown.

Old feature counts remain presence/session counts. New operations report observed
transitions, capped per operation and session with clear CRM completeness limits.
Attempt/retry links remain existing installation-scoped opaque IDs. A new operation
is required for a new Help activation or playback load; callbacks repeating the same
step cannot manufacture another operation or claim a new user action.
Settings/configured intent and effective output facts remain distinct. No source
hash, URL, title, notes, tag contents, artwork, raw errors or browser-profile identity
is sent. Variant relation is computed locally from durable history and emitted only
as a categorical observation; unrelated attempts cannot imply same source.

## Question-to-evidence matrix

| Question | Prospective producer facts | Independent proof | Causal limit |
| --- | --- | --- | --- |
| Did another export intent share an item folder? | Same-item intent relation, owned namespace, new/reused outcome, per-operation phase | Physical directories, canonical history, media hashes and probes | No source identity is recoverable from the event |
| Was media created or validated and reused? | Explicit created/reused transition, validation result | Actual filesystem commits versus unchanged hashes | A completed run alone is insufficient |
| Where did an attempt fail? | Exact last entered phase, typed allowlisted failure, parent attempt and retry | Controlled fault in real owner, persisted events, file/process state | Missing terminal event may reflect lost delivery/consent/exit |
| Why did local conversion fail? | Structured local_conversion_failed reason/detail from actual worker and durable history outcome | Real converter failure through UI event, serializer, backend, D1, CRM | Raw exception text remains local |
| Did Help selection dispatch and show a modal? | Requested/returned/selected/dispatched/shown/blocked/closed sequence | Native mouse input, visible dialog, grab and lifecycle state | Missing Tcl selection cannot distinguish lost callback from dismissal |
| Did playback start or fail after a request? | Per-load request/readiness/play/failure/close observations | Real provider state plus native visible response | Intent is not evidence that playback actually began |
| Did recovery repair interrupted work? | Existing durable recovery decision linked to original attempt | Restart and actual history/media/staging preservation | Unobserved past work is not retroactively emitted |
| Did a flow stop progressing? | Last observed phase and explicit cancellation/close/recovery | Controlled interrupted owner and fresh launch | Missing follow-up is incomplete observation, not proven hang |
| Do repeated actions suggest usability friction? | Repeated distinct operations, blocked/closed outcomes, bounded duration | Replay same native interaction with visible outcome | Frequency is not user frustration or motivation |
| Are new facts actually available? | Instrumentation/build/platform coverage and accepted event shape | New preview D1 rows and CRM readback | Old schema2 detailed rows are not equivalent coverage |
| Does refusal prevent new observations? | No producer acceptance/outbox/send after denial/off | Durable state and D1 before/after snapshots across launches | A local callback return is not a server receipt |
| Are retries immutable and correlated? | Stable event identity, operation/attempt/retry IDs and steps | Forced delivery failure/replay, exact D1 equality, withdrawal tests | Outbox limits and missing rows remain visible |

## Blinded validation

Produce new preview-only events through actual producers where possible, retain a
separate private fixture manifest, then give the investigator only persisted events,
settings and attempt history. Include both user-reported regression classes, local
conversion/playback failure, recovery and interrupted flow. Record initial hypothesis,
owner/stage and ambiguity before revealing ground truth. Independently reproduce and
verify the correction. A direct serializer probe proves transport only and must be
labeled separately from actual native/package producers.

Full positive/denied/off native packaged release gates remain mandatory after the
final signed artifact freeze. Source diagnostics and this plan are not release proof.


## Current implementation and limits

The new source follows existing download, local conversion, Help, player and
layout owners. Operation UUIDs are random; a retained operation has at most64
observations, and at most256 operation entries are remembered. After eviction,
a later observation opens a fresh sequence; it cannot reconstruct old steps.
Missing ordinals and reported dropped observations remain explicit. Drop counters
cover this operation recorder, not every possible network loss or legacy event.
There is no claim that all unseen failures are diagnosable.

Unexpected errors include allowlisted built-in types and the last shipped
first-party module/line found in at most64 traceback frames. The marker says
first_party_frame: this is a call-site observation, not proof of the root cause.
No traceback text, function locals, filenames or paths are serialized. A clean
build bundles its source commit; dirty or non-Git builds report unknown and cannot
satisfy the new exact packaged-source telemetry gate.

Consent denial atomically rotates a private collection epoch in existing settings;
legacy denial without an epoch is migrated. Outbox epochs never appear on the
wire. This prevents a failed purge followed by re-enable/restart from sending old
observations. Both sinks recheck permission/epoch/generation. An already in-flight
request cannot be unsent, and an OS-denied file removal can leave invalidated old
bytes on disk until cleanup succeeds.

Current source tests and native/source outbox receipts do not establish preview
routing or final signed behavior. Recovery/interruption, held-out unexpected
failure through D1/CRM, source identity relations, visual CRM, blind packet and
all signed release gates remain pending until their receipts are attached.
